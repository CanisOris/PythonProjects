Python 3 Exception Handling Variations

In Python 3, exception handling centers on try, except, else, and finally blocks, alongside raising, chaining, and grouping exceptions.

1. Basic try / except

Catches a specific exception type so the program can recover or report a clear message instead of crashing.

raw_value = "42"
try:
    number = int(raw_value)
except ValueError:
    print(f"Cannot convert {raw_value!r} to an integer.")

2. Multiple except Blocks (Different Types)

Handles different exception classes with distinct recovery logic. Python checks except clauses in order from top to bottom and runs the first matching handler.

def read_first_line(path):
    try:
        with open(path, "r", encoding="utf-8") as f:
            return f.readline()
    except FileNotFoundError:
        return None
    except PermissionError:
        print(f"Permission denied reading {path}")
        return None

3. Tuple of Exceptions in One except

Handles multiple distinct exception types the same way without repeating the block.

try:
    result = 10 / int("0")
except (ValueError, ZeroDivisionError) as exc:
    print(f"Invalid calculation input: {exc}")

4. Capturing the Exception Object (as exc)

Binds the raised exception instance to a variable so you can inspect its message, attributes, or type.

try:
    data = {"a": 1}
    print(data["missing_key"])
except KeyError as err:
    print(f"Missing key: {err!r}")

5. try / except / else

The else block runs only if the try block completes without raising an exception. Keeping non-guarded post-success code in else avoids accidentally catching exceptions raised outside the risky operation.

try:
    count = int("10")
except ValueError:
    print("Invalid count")
else:
    print(f"Successfully parsed count: {count}")

6. try / except / finally (and try / finally)

The finally block always runs before leaving the try structure—whether an exception occurred, was caught, went uncaught, or a return/break/continue executed. Use it for cleanup such as closing connections or releasing locks.

conn = None
try:
    conn = open_db()
    run_query(conn)
except RuntimeError as exc:
    print(f"Query failed: {exc}")
finally:
    if conn is not None:
        conn.close()

7. Catch-All except Exception: (and Why to Avoid Bare except:)

Catching Exception handles standard runtime errors while letting KeyboardInterrupt and SystemExit (which inherit from BaseException, not Exception) propagate cleanly. Avoid bare except: unless you immediately re-raise after logging.

try:
    process_item()
except Exception as exc:
    print(f"Unexpected error: {exc}")

8. Re-Raising with raise

Logs or partially handles an error inside except and re-raises the exact same exception with its original traceback intact.

try:
    load_config()
except OSError:
    print("Failed to load config; propagating error.")
    raise

9. Raising & Chaining Exceptions (raise ... from ...)

  • raise NewError("msg") from original_exc — Explicitly links a new exception to its root cause (__cause__).
  • raise NewError("msg") from None — Suppresses the previous exception context in the traceback when you want a clean error message.
def parse_port(raw_port):
    try:
        return int(raw_port)
    except ValueError as exc:
        raise ValueError(f"Invalid port number: {raw_port!r}") from exc

10. Exception Groups (except* — Python 3.11+)

Handles ExceptionGroup / BaseExceptionGroup instances (such as multiple concurrent errors raised together) by matching subgroups of exceptions independently.

try:
    raise ExceptionGroup("batch failures", [ValueError("bad row"), KeyError("missing col")])
except* ValueError as eg:
    print(f"ValueErrors ({len(eg.exceptions)}): {eg.exceptions}")
except* KeyError as eg:
    print(f"KeyErrors ({len(eg.exceptions)}): {eg.exceptions}")
