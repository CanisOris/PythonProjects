Python 3: Generator vs. Regular Function

← Back to index

In Python 3, a regular function (def with return) executes from start to finish and returns a single value (or None) at once, whereas a generator (def with yield, or a generator expression (expr for ...)) pauses execution at each yield, yields one value at a time on demand, and resumes right after that yield when the next item is requested.

Core Differences at a Glance

Dimension Regular Function (return) Generator Function (yield) / Generator Expression
Definition Uses return (or falls off the end) Uses yield or yield from (or (x for x in ...) syntax)
Call result Immediately runs body and returns the result Calling it returns a generator object (an iterator) without running the body yet
Execution model Runs to completion in one go; local frame is discarded on return Pauses at each yield, preserving local variables and instruction pointer; resumes on next()
Number of values Produces one value (could be a list, tuple, dict, etc.) Produces a sequence of zero, one, many, or infinite values over time
Memory profile Materializes full collections in memory if returning lists/tuples Yields items lazily one at a time (O(1) per step for streaming)
Reusability Can be called repeatedly whenever needed Single-pass / exhausted once consumed; call the generator function again for a fresh iterator
Completion signal Returns a value or raises an exception Raises StopIteration when the body finishes (handled automatically by for, list(), sum(), etc.)

How Execution Works Under the Hood

  1. Lazy start: Calling gen = my_generator() does not execute the first line of my_generator. It creates and returns a generator object implementing both the iterator (__iter__, __next__) and generator protocols.
  2. Step-by-step suspension: The first next(gen) runs until the first yield value, hands value to the caller, and freezes local state. The next next(gen) resumes immediately after yield value until the next yield or return.
  3. return inside a generator: A return some_value inside a generator function does not yield some_value to a normal for loop—it terminates the generator and attaches some_value as .value on the raised StopIteration(some_value) exception (which yield from can capture).

Code Comparison

# Regular function: builds and returns the entire list at once
def get_txt_files_list(filenames):
    matches = []
    for name in filenames:
        if name.endswith(".txt"):
            matches.append(name)
    return matches


# Generator function: yields matching names lazily one by one
def iter_txt_files(filenames):
    for name in filenames:
        if name.endswith(".txt"):
            yield name


sample = ["notes.txt", "data.csv", "todo.txt", "script.py"]

eager_result = get_txt_files_list(sample)
print("List:", eager_result)

gen = iter_txt_files(sample)
print("Generator object:", gen)
print("First item:", next(gen))
print("Remaining items:", list(gen))  # Consumes the rest; gen is now exhausted
print("Second pass on same gen:", list(gen))  # Empty []

Generator Protocol Methods (send, throw, close)

Beyond next(gen) / for item in gen:, generator objects expose control methods:

  • gen.send(value) — Resumes execution and passes value in as the result of the current (yield ...) expression (use gen.send(None) or next(gen) to start a fresh generator).
  • gen.throw(exc_type[, exc_val[, tb]]) — Raises a specified exception at the point where the generator is paused so internal try...except blocks can handle or clean up.
  • gen.close() — Raises GeneratorExit at the paused yield so finally blocks run cleanly, then marks the generator closed (subsequent next() calls raise StopIteration).

When to Choose Which

  • Use a regular function (return) when: You need a single computed result, random/indexed access (result[2]), len(result) upfront, or small datasets where eager evaluation is simpler and clearer.
  • Use a generator (yield / generator expression) when: Streaming large files, database cursors, or multi-step pipelines; processing items as soon as they arrive; stopping early (next(), any(), break) without computing remaining items; or modeling unbounded/infinite sequences.
