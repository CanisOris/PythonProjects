What Is a Python Decorator?

A Python decorator is a callable (usually a function or class) that takes another function or class, adds or modifies its behavior without permanently altering its source code, and returns a replacement object.

Under the hood, placing @decorator above a function definition is syntactic sugar for passing that function into the decorator and rebinding its name:

Python — Syntactic Sugar 
def greet(name):
    return f"Hello, {name}!"

greet = decorator(greet)

Custom Decorator Patterns

1. Basic Decorator with functools.wraps (Timing / Logging)

Always apply @functools.wraps(func) to your inner wrapper so the decorated function retains its original __name__, __doc__, and signature metadata.

Python — Timer Decorator 
import functools
import time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            print(f"{func.__name__} took {elapsed:.4f}s")
    return wrapper

@timer
def compute_sum(n):
    """Return the sum of integers from 0 to n - 1."""
    return sum(range(n))

print(compute_sum(1_000_000))
print(compute_sum.__name__)  # "compute_sum" (thanks to @functools.wraps)

2. Decorator That Accepts Arguments (Decorator Factory)

When a decorator takes configuration parameters (such as retry counts or permissions), add one outer factory function that returns the actual decorator.

Python — Parameterized Retry Decorator 
import functools
import time

def retry(max_attempts=3, delay=0.1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            for attempt in range(1, max_attempts + 1):
                try:
                    return func(*args, **kwargs)
                except Exception as exc:
                    if attempt == max_attempts:
                        raise
                    print(f"Attempt {attempt} failed ({exc}); retrying in {delay}s...")
                    time.sleep(delay)
        return wrapper
    return decorator

@retry(max_attempts=3, delay=0.05)
def flaky_call():
    raise ConnectionError("Temporary network drop")

When to Use Decorators

  • Cross-cutting concerns: Logging, timing/metrics, authentication checks, caching, and rate limiting shared across many functions.
  • Registration patterns: Registering web routes, CLI subcommands, event listeners, or plugins (e.g., @app.get("/items")).
  • Managed attributes & constructors: Turning methods into computed attributes via @property or defining factory methods with @classmethod.
  • Clean domain logic: Isolating repetitive setup/teardown guardrails from core business logic.

When NOT to Use Decorators

  • Core business logic or hidden mutations: Silently altering arguments, swallowing exceptions, or changing return shapes obscures data flow.
  • Deeply stacked chains: Layering 4–5 custom decorators on one function complicates debugging, stack traces, and readability.
  • One-off behaviors: When logic is used in only one or two places, an explicit helper call or a context manager (with ...:) is clearer.
  • Heavy introspection without @wraps: Omitting functools.wraps breaks doc generators, type tools, and test mocking.

All Standard Library Decorators & Usage Examples

Python provides built-in decorators (available without imports) alongside standard library decorators organized by module for caching, classes, OOP interfaces, context managers, and typing.

builtins (No Import Required)

1. Core Built-in Class & Descriptor Decorators

Decorator Purpose
@property Turns a method into a read-only attribute; pairs with @<name>.setter and @<name>.deleter.
@classmethod Binds the class (cls) rather than an instance (self) as the first argument; ideal for factory constructors.
@staticmethod Defines a utility function inside a class namespace that receives neither self nor cls.
Python — @property, @classmethod, @staticmethod 
class Temperature:
    def __init__(self, celsius: float):
        self._celsius = celsius

    @property
    def fahrenheit(self) -> float:
        return (self._celsius * 9 / 5) + 32

    @fahrenheit.setter
    def fahrenheit(self, value: float) -> None:
        self._celsius = (value - 32) * 5 / 9

    @classmethod
    def from_fahrenheit(cls, f: float) -> "Temperature":
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_freezing(celsius: float) -> bool:
        return celsius <= 0.0

t = Temperature.from_fahrenheit(212)
print(t.celsius, t.fahrenheit, Temperature.is_freezing(-2))
functools

2. Higher-Order Function, Caching & Dispatch Decorators

Decorator Purpose
@wraps(wrapped) Copies metadata (__name__, __doc__, annotations) onto a wrapper function.
@cache Unbounded memoization cache (equivalent to @lru_cache(maxsize=None)).
@lru_cache(maxsize=128) Least-Recently-Used memoization cache with configurable size and .cache_info() / .cache_clear().
@cached_property Computes a property once per instance and caches the value in the instance's __dict__.
@total_ordering Generates all rich comparison methods (<=, >, >=) from __eq__ plus one ordering method (e.g., __lt__).
@singledispatch Turns a function into a single-dispatch generic function overloaded by first-argument type via @fn.register.
@singledispatchmethod Same as @singledispatch, designed for methods on a class (dispatches on the first argument after self/cls).
Python — functools Decorators 
from functools import cache, lru_cache, cached_property, total_ordering, singledispatch

@cache
def fib(n: int) -> int:
    return n if n < 2 else fib(n - 1) + fib(n - 2)

@lru_cache(maxsize=256)
def fetch_config(env: str) -> dict:
    return {"env": env}

@total_ordering
class Version:
    def __init__(self, major: int, minor: int):
        self.pair = (major, minor)

    def __eq__(self, other) -> bool:
        return self.pair == other.pair

    def __lt__(self, other) -> bool:
        return self.pair < other.pair

    @cached_property
    def label(self) -> str:
        return f"v{self.pair[0]}.{self.pair[1]}"

@singledispatch
def serialize(value):
    return str(value)

@serialize.register(list)
def _(value):
    return ", ".join(map(str, value))
dataclasses & enum

3. Data Container & Enumeration Decorators

Decorator Module Purpose
@dataclass dataclasses Auto-generates __init__, __repr__, __eq__, and optional ordering/immutability from type annotations.
@unique enum Ensures an Enum class has no duplicate member values (raises ValueError on duplicates).
@verify(...) enum Validates enum constraints such as UNIQUE, CONTINUOUS, or NAMED_FLAGS (Python 3.11+).
Python — @dataclass and @unique 
from dataclasses import dataclass
from enum import Enum, unique

@dataclass(frozen=True)
class Point:
    x: float
    y: float

@unique
class HttpStatus(Enum):
    OK = 200
    NOT_FOUND = 404
abc

4. Abstract Base Class Decorators

Decorator Purpose
@abstractmethod Declares a method that subclasses must implement before the class can be instantiated.
Python — @abstractmethod 
from abc import ABC, abstractmethod

class Exporter(ABC):
    @abstractmethod
    def export(self, payload: dict) -> str:
        raise NotImplementedError
contextlib

5. Context Manager Decorators

Decorator Purpose
@contextmanager Turns a generator function with a single yield into a synchronous with context manager.
@asynccontextmanager Turns an async generator function into an async with context manager.
Python — @contextmanager 
from contextlib import contextmanager
import tempfile, shutil

@contextmanager
def temp_workspace():
    path = tempfile.mkdtemp()
    try:
        yield path
    finally:
        shutil.rmtree(path)
typing & warnings

6. Static Type-Checking & Deprecation Decorators

Decorator Module Purpose
@overload typing Declares multiple type signatures for a function before its concrete implementation.
@final typing Indicates to type checkers that a method cannot be overridden or a class cannot be subclassed.
@override typing Verifies at type-check time that a method actually overrides a parent class method (Python 3.12+).
@runtime_checkable typing Allows a typing.Protocol to be checked at runtime with isinstance() / issubclass().
@dataclass_transform typing Marks a custom decorator/metaclass as providing dataclass-like behavior for static type checkers.
@deprecated(msg) warnings Marks a function, class, or overload as deprecated at runtime and for static analyzers (Python 3.13+).
Python — typing & warnings Decorators 
from typing import overload, final, override, runtime_checkable, Protocol
from warnings import deprecated

@overload
def parse(raw: str) -> int: ...
@overload
def parse(raw: bytes) -> int: ...
def parse(raw: str | bytes) -> int:
    return int(raw)

@runtime_checkable
class Closeable(Protocol):
    def close(self) -> None: ...

class BaseService:
    def run(self) -> None:
        pass

@final
class ConcreteService(BaseService):
    @override
    def run(self) -> None:
        print("Running")

@deprecated("Use ConcreteService.run() instead")
def legacy_run() -> None:
    pass
unittest, atexit, types, asyncio & weakref

7. Testing, Lifecycle & Runtime Utility Decorators

Decorator Module Purpose
@unittest.skip / @skipIf / @skipUnless unittest Unconditionally or conditionally skips a test method or test class.
@unittest.expectedFailure unittest Marks a test as a known failure so it does not fail the test suite until fixed.
@unittest.mock.patch unittest.mock Temporarily replaces an object or attribute with a MagicMock during a test function.
@atexit.register atexit Registers a cleanup function to run automatically when the Python interpreter exits normally.
@types.coroutine types Converts a generator function into a coroutine object compatible with await.
@weakref.finalize weakref Registers a finalizer callback invoked when an object is garbage-collected.
Python — atexit & unittest Decorators 
import atexit
import sys
import unittest
from unittest.mock import patch

@atexit.register
def on_shutdown():
    print("Flushing buffers before exit...")

class SampleTests(unittest.TestCase):
    @unittest.skipIf(sys.platform == "win32", "POSIX-only test")
    def test_posix_permissions(self):
        self.assertTrue(True)

    @patch("builtins.print")
    def test_output(self, mock_print):
        print("hello")
        mock_print.assert_called_once_with("hello")

Terms and Commands Used

A quick reference to the concepts and commands covered on this page.

Key terms

Decorator
A callable applied to a function or class to add or alter behavior and return its replacement.
Wrapper
A callable surrounding another callable with extra behavior.
Decorator factory
A function accepting configuration and returning a decorator.
Metadata
Information such as a function's name, documentation, and annotations.
Caching
Saving results so later calls can reuse them.
Descriptor / Dispatch
A descriptor controls attribute access; dispatch chooses an implementation, for example by argument type.

Key commands

@property / @classmethod / @staticmethod
Expose a managed attribute, a method receiving the class, or a method receiving no automatic instance or class.
@functools.wraps
Copies function metadata to a wrapper and sets its __wrapped__ attribute.
@cache / @lru_cache
Cache results for hashable arguments, with no size limit or a configurable least-recently-used limit.
@cached_property
Computes a property on first access and stores its value on the instance.
@dataclass
Generates methods such as __init__ and __repr__ from declared fields.
@abstractmethod
Marks a method that concrete subclasses of an abstract base class must implement.
@contextmanager
Turns a generator function yielding once into a context-manager factory.
@overload
Declares alternative signatures for type checkers; a separate implementation handles runtime calls.
