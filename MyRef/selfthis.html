Using self. vs. Not Using self. in Python

← Back to index

Using self.trust_score = trust_score stores the value on the specific object instance so other methods on that object can read or update it later. Without self. (just trust_score = trust_score), it is only a local variable inside __init__ and disappears as soon as __init__ finishes running.

Key Differences

Aspect With self. (self.trust_score = trust_score) Without self. (trust_score = trust_score)
Lifetime Lasts as long as the object instance exists Destroyed as soon as __init__ finishes
Where it lives Stored on the instance (obj.trust_score) Lives only in __init__'s local scope
Access in other methods Accessible anywhere via self.trust_score Raises NameError in other methods
Per-instance state Each strategy instance keeps its own value Nothing is saved on the instance

Example: What Happens When You Omit self.

class BrokenStrategy:
    def __init__(self, name, trust_score):
        self.name = name
        # Missing 'self.': trust_score is only a temporary local variable
        trust_score = trust_score

    def report_trust(self):
        # Fails with NameError because trust_score was not saved on the instance
        return f"{self.name} has trust score {trust_score}"

In self.trust_score = trust_score, the right-hand trust_score is the parameter passed into __init__, and self.trust_score is the attribute attached to that specific instance (self).
